# Onshape AI Studio

A locally hosted AI-assisted workspace for Onshape. The browser UI communicates with a local FastAPI backend; Onshape credentials and signed requests remain server-side.

## Current implementation

- Personal Onshape API-key request signing using the documented HMAC-SHA256 scheme.
- List documents, create a document, inspect document elements, and read Part Studio feature definitions.
- Local Ollama and cloud OpenAI-compatible AI provider adapters.
- Natural-language CAD planning with FeatureScript draft output.
- Explicit confirmation and payload-shape checks on the feature-write endpoint.
- GET response caching, bounded concurrency, a bounded retry for transient 5xx responses, and 429/402 handling.
- App-local successful-request counters (not a substitute for Onshape's account usage page).

## Requirements

- Python 3.11+
- Node.js 20+
- An Onshape API key created on the same Onshape stack as the account.
- Ollama running locally, or a cloud AI API key.

## 1. Configure the backend

From the repository root:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Edit `.env` and set `ONSHAPE_ACCESS_KEY` and `ONSHAPE_SECRET_KEY`. For cloud AI, set `AI_PROVIDER=cloud` and `CLOUD_AI_API_KEY`. For Ollama, leave `AI_PROVIDER=ollama` and make sure the configured Ollama model is installed and the local Ollama service is running.

Keep `.env` private. Never paste credentials into chat, the browser UI, or GitHub.

Start the backend:

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Backend health: http://127.0.0.1:8000/api/health  
Interactive API docs: http://127.0.0.1:8000/docs

## 2. Start the frontend

Open a second terminal from the repository root:

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

## Security and execution model

- The frontend never receives Onshape API credentials. Requests are signed by the backend.
- Personal API keys authenticate the application as the key owner; they do not authenticate separate users. OAuth2 is required for Onshape App Store distribution.
- Bind the development server to localhost. Do not expose it to the public internet without user authentication, CSRF protections, TLS, secret management, and deployment hardening.
- AI plans are proposals. The assistant must not claim an operation has executed unless the Onshape API confirms it.
- Feature writes require an explicit confirmation flag and a payload containing the documented feature envelope. Verify each feature's exact schema in the Onshape API Explorer before submitting it.
- FeatureScript generated by the AI is draft source text; it is not automatically published or executed.

## API usage protection

Onshape applies endpoint-specific rate limits and annual API-call allocations. The app caches selected GET responses, limits concurrency, retries only once for transient 5xx responses, and surfaces 429 with `Retry-After`. A 402 response stops the operation and directs the user to check Onshape usage. App counters only cover requests made through this running instance; Onshape Developer settings remain authoritative.
